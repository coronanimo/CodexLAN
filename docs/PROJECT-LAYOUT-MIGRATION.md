## 权限模型

- 项目以数据库中的 ID、绝对路径、`ownerId` 和 `memberIds` 为准，不以盘符或用户名文件夹判断权限。
- 已有项目保持原 owner，默认不向其他人开放。所有者在“项目管理 → 授权”中选择协作者。
- 授权覆盖项目文件、项目聊天和队列，包括已有聊天；界面会明确说明这一点。协作者可以执行任务、上传附件、操作聊天与队列，不能管理项目或再授权。当前版本没有只读角色或项目内的私有聊天。
- 已授权的管理员也可以管理项目。未被授权的管理员不会自动出现在该项目的访问列表中。
- 已有任意绝对目录由管理员添加后授权；普通成员可以留空目录创建新项目，不能通过填写已有路径给自己授权。
- `workspaceRoot` 仅表示默认新建目录，切换后为 `D:\Code`；它不限制添加其他盘符和目录。
- 小规模协作者 ID 列表与原 owner 一起保存在既有 SQLite 项目记录中。无需升级数据库 schema，旧记录不含列表时仍仅 owner 可访问。

## 正式切换

先完成正在执行的 CodexLAN 任务，并关闭仍在修改旧 F 盘项目的程序。其他项目准备后产生的新修改会触发保护，脚本将拒绝覆盖，需先合并并刷新准备。不要在切换验收前同时编辑新旧两个副本。

从外部 PowerShell 执行：

```powershell
& "$env:LOCALAPPDATA\Programs\CodexLAN\Switch-ProjectLayout.ps1" -Action Cutover
```

脚本会停止当前服务，使用已固定的代理配置登记旧、新路径中的原生 Codex 历史，对最新 SQLite 做一致快照并验证业务字段；随后更新项目路径、切换到候选发布版本，并继续使用固定的 `.codexlan\data`。账号、会话、项目 ID、owner、已有协作者授权、队列及顺序、设置、异步回答和恢复数据均保留。不会修改原生 Codex 历史数据库。

旧 F 盘项目目录先重命名保存到 `F:\GPTData\.layout-backups\<本次迁移目录>`。除退役 Meta0 外，原路径成为指向 D 盘代码的兼容联接，避免历史附件和其他程序中的旧路径立即失效。这些联接只是兼容入口，不构成用户权限边界，也不在 F 盘保存第二套代码。

现有登录自启动任务和固定 launcher 继续使用，不另装服务或第二个自启动。启动后等待 Codex 后端 ready；失败尝试恢复原数据库、配置、发布版本和目录。阶段记录保存在迁移目录的 `switch.json`。

## 验收与旧目录清理

确认项目列表、任意目录添加、历史聊天分页、旧聊天继续执行、队列顺序、附件，以及授权/撤销后两位用户的访问行为。共享授权需要用户明确选择，不会自动把现有聊天分享出去。Meta0 仅验收代码和知识保留、数据分离、无目录联接，不验收旧程序运行。

验收通过后，再执行：

```powershell
& "$env:LOCALAPPDATA\Programs\CodexLAN\Switch-ProjectLayout.ps1" -Action Complete
```

仅将本次迁移记录中的 F 盘旧目录备份移入回收站，并逐项报告实际路径。不清空回收站，不删除 `F:\QuantData`，不处理其他目录。完成前可回退：

```powershell
& "$env:LOCALAPPDATA\Programs\CodexLAN\Switch-ProjectLayout.ps1" -Action Rollback
```

回退恢复原数据库和路径，新版本切换后新增的数据保留在迁移目录，不自动合并进旧数据库。应先完成验收再开展新工作。Complete 后自动目录回退不可用；数据库备份仍保留。
